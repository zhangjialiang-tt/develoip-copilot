# 协议与激励启发式（rtl-to-testbench）

> 本 skill 无协议提取工具。DUT 的协议/行为必须由 agent 基于工具证据与用户说明推断，并标注置信度。本文件给出可复用的推断线索与置信度判定规则，降低输出差异。

## 证据来源（按可信度排序）

1. **用户说明**（最高）：协议行为说明、已知测试向量、时序图 → 置信度可标"高"
2. **工具事实**：`extract_interfaces.py` 端口方向/位宽、`scan_clock_reset.py` 时钟边沿/复位类型 → 用于交叉验证，不直接给出协议
3. **命名与结构启发**：端口名、状态机（`rtl-architecture-analysis` 的 fsm 启发式）、握手信号 → 中/低置信度，需用户确认

## 常见协议线索

| 线索 | 推断 | 典型置信度 |
| --- | --- | --- |
| 端口含 `valid`/`ready` 且成对 | AXI-Stream 类流握手 | 中（需 valid/ready 关系确认） |
| 端口含 `req`/`ack` | 请求-应答 | 中 |
| 端口含 `cs`/`sclk`/`mosi`/`miso` | SPI 类 | 中 |
| 端口含 `scl`/`sda` | I2C 类 | 中 |
| 参数含 `$clog2(DEPTH)`/`ADDR_W` | 含地址/深度，疑似内存映射或 FIFO | 低-中 |
| 单 `clk`/`rst` + 数据入出 | 组合/流水变换，协议简单 | 中-高（若用户给说明则高） |

## 激励策略选择

- **定向 + self-check**：优先。用参考模型（Python/公式）在 tb 内实时比较输出，避免依赖固定向量（固定向量置信度低且易过期）。
- **随机 + 约束**：覆盖边界（首拍、空满、背压）。种子固定以便复现。
- **固定向量**：仅当用户提供已知向量，或 DUT 行为无法用参考模型表达时。

## 置信度标注规则

- **高**：用户明确说明，或工具事实与说明完全吻合。
- **中**：由命名/结构推断，与已知协议家族一致，但缺少关键时序细节。
- **低**：纯命名启发，无用户确认，或与其他线索冲突。
- 任何"低"置信度项**必须**列入 verification-plan 的"未确定项"，并在生成前请求用户确认或显式标注假设。

## 边界与诚实声明

- 不臆测协议细节（如突发长度、打包顺序）。
- 推断结论与工具事实冲突时，以工具事实为准并标注冲突。
- 协议未被覆盖时，在 verification-report 的"未确定项与风险"中说明，不声称已验证。
