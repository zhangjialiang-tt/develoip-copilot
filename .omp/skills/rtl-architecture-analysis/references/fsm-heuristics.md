# FSM / 协议边界 / 数据流 识别启发式

本 skill 的确定性工具只覆盖**接口、层级、时钟、复位**。状态机、协议边界、
数据流三项目前**没有专用工具**，由 `rtl-analyst` 基于工具输出与源码人工识别。
本文件给出可复现的启发式与置信度标注规范，避免结论不可验证。

## 1. 状态机（FSM）识别

**证据来源**：`scan_clock_reset` 的敏感表 + `extract_interfaces` 的端口 + 源码。

**启发式**：
- 模块内存在 `typedef enum ... state_t` 与 `state` / `next_state` 寄存器对 → 高置信。
- 存在 `always @(posedge clk ...)` 块，内部为 `case (state) ... endcase` 且驱动 `next_state` → 高置信。
- 仅存在一组带复位、随 `clk` 更新的寄存器，但无 `case`/枚举 → 可能是 FSM，标注"中置信，待确认编码方式"。
- 无任何状态寄存器 → 标注"未发现状态机（组合/数据流模块）"。

**输出要求**：在 `dataflow.md` 或 `risk-notes.md` 列出状态集合、复位初值、转移触发条件；
每条标注置信度（高/中/低）。

## 2. 协议边界识别

**启发式**（按优先级）：
- 端口名命中已知协议关键字：`axi*`、`axil*`、`apb*`、`ahb*`、`avalon*`、`i2c*`、`spi*`、
  `uart*`、`gmii*`、`rgmii*`、`mdio*`、`s_*`/`m_*`（AXI 风格）、`tvalid`/`tready`/`tdata` 等 → 高置信。
- 端口分组呈现典型握手：`*_valid` / `*_ready` / `*_data` / `*_addr` / `*_wen` → 中-高置信。
- 仅有时钟+数据+使能，无标准握手名 → 标注"自定义/未知协议，中置信"。

**输出要求**：在 `dataflow.md` 的"协议边界"表填写协议类型与关键信号；无法判定时填"未知"并标注置信度。

## 3. 数据流识别

**证据来源**：`extract_interfaces` 端口 + `build_hierarchy` 层级 + 源码赋值。

**启发式**：
- 沿 `assign` 与 `always` 块追踪信号从输入端口/寄存器到输出端口/下一级实例的连通路径。
- 跨实例的数据流依据 `build_hierarchy` 的父子连接（`.port (signal)`）拼接。
- 组合路径 vs 时序路径：被 `always @(posedge clk)` 打拍的信号为时序路径。

**输出要求**：在 `dataflow.md` 的"关键数据通路"表列出 起点→终点→途径模块→位宽→关键控制；
置信度按"静态可确认"给高，"需运行仿真/读设计文档确认"给中/低。

## 置信度标注规范
- **高**：工具输出或明显命名/结构证据直接支持。
- **中**：结构合理推断，但缺少运行/文档证据。
- **低**：仅命名暗示，无法静态确认。
- 任何"低"或"未确定"项必须在 `risk-notes.md` 的"未确定项"表中列出原因与需用户补充的信息。
