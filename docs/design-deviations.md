# develoip-copilot 设计偏差记录

> 文档用途：记录实现必须偏离 design.md v2.1 的情况
> 适用对象：实施者、架构决策者、代码评审者
> 更新频率：仅当必须偏离时记录

---

## 核心原则

**禁止因为"实现方便"直接修改架构。**

---

## 允许偏差的理由

仅以下理由可以记录偏差：

1. **OMP 实际能力与设计假设不符**
   - OMP 不支持某个预期功能
   - OMP 行为与设计假设不一致

2. **Fixture 证明当前结构无法工作**
   - 多个 Fixture 无法通过验证
   - 当前结构导致无法处理的场景

3. **真实工程案例证明职责边界错误**
   - 真实项目证明当前划分不合理
   - 真实案例必须合并或拆分职责

4. **Tool 方案无法满足正确性或性能要求**
   - Python CLI 无法满足性能要求
   - Tool 方案无法保证正确性

5. **实现发现安全、数据损坏或工作区破坏风险**
   - 发现明确的安全漏洞
   - 发现数据损坏风险
   - 发现工作区破坏风险

6. **设计文档内部存在不可同时满足的矛盾**
   - 不同章节之间矛盾
   - 不同设计要求之间冲突

## 偏差处理流程

### 1. 提出偏差

当发现必须偏离设计时：

1. 记录在本文档
2. 说明原因和证据
3. 提出替代方案
4. 评估对现有设计的影响

### 2. 评审偏差

轻度偏差：
- 记录即可
- 不影响核心架构语义

中度偏差：
- 暂停实施
- 记录影响
- 判断是否需要更新 design.md

重度偏差：
- 立即停止实施
- 正式评审
- 必须更新 design.md

### 3. 决策偏差

根据偏差严重程度和影响范围决策：

- 接受偏差并更新 design.md
- 接受偏差但不更新 design.md（仅实现细节）
- 拒绝偏差，重新设计

### 4. 更新追踪

决策后必须：

1. 更新 `docs/traceability.md`
2. 如更新 design.md，更新 `docs/design-constraints.md`
3. 同步更新相关实施计划

---

## 禁止行为

- ❌ 因为"实现方便"记录偏差
- ❌ 在未记录偏差的情况下修改核心架构
- ❌ 通过偏差记录绕过 `docs/design-constraints.md` 的十条设计不变量
- ❌ 在重度偏离时只记录不评审
