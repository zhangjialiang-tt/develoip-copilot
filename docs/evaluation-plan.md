# develoip-copilot 评估计划

> 文档用途：定义 Fixture 和真实样例，指导能力验收
> 适用对象：实施者、验收人员、质量保障
> 更新频率：每个 Milestone 开始前更新 Fixture 列表
> 核心原则：没有测试样例，不开始写分析工具

---

## 验证层分类

### A. Tool Test

验证确定性行为：

```text
输入文件
→ Python CLI
→ exit code
→ stdout/stderr
→ JSON 或文件输出
```

**使用方式**：pytest 和 golden file

**验证对象**：Python CLI 的确定性输入输出

**不适合**：模型行为、复杂推理、语义分析

---

### B. Agent Eval

验证模型行为：

```text
任务描述
→ 上下文
→ 预期必须包含
→ 禁止出现
→ 评分 rubric
```

**使用方式**：人工评估或模型评估，不宜使用普通单元测试断言全文

**验证对象**：专业分析、产物质量、推理过程

**不适合**：确定性输入输出

---

### C. Skill Eval

验证流程、路由和失败处理：

```text
用户任务
→ Skill 匹配
→ Procedure 执行
→ Agent 调用
→ 失败处理
→ 产物生成
```

**使用方式**：端到端场景测试

**验证对象**：路由正确性、流程完整性、失败处理

**不适合**：单个 Agent 的专业质量

---

### D. OMP Smoke

验证原生能力集成：

```text
Skill 被发现
→ Agent 被调用
→ references 可读
→ 输出可交接
→ Tool 可执行
→ 失败可报告
```

**使用方式**：真实 OMP 环境测试

**验证对象**：OMP 发现、调用、交接机制

**不适合**：专业能力正确性

---

## 责任边界

| 验证层 | 主要责任 | 不属于 |
|--------|---------|--------|
| Tool Test | CLI 确定性输入输出 | 模型行为、复杂推理 |
| Agent Eval | 专业分析和产物质量 | CLI 路由、失败处理 |
| Skill Eval | 流程、路由和失败处理 | 单个 Agent 的专业质量 |
| OMP Smoke | 原生发现、调用和交接 | 专业能力正确性 |

## Milestone 1 验收标准（冻结）

### Tool Test

#### 正常参数

- [ ] CLI 返回 `0`
- [ ] stdout 为合法 JSON 或预期格式
- [ ] stderr 不混入结构化 stdout
- [ ] 输出符合 CLI 规范

#### 缺少参数

- [ ] CLI 返回非零状态
- [ ] 错误信息明确指出缺失参数
- [ ] 不会崩溃或产生未定义行为

#### 错误参数

- [ ] CLI 返回非零状态
- [ ] 错误信息明确指出参数错误
- [ ] 不会猜测缺失参数

---

### Agent Eval

#### 正常场景

- [ ] 能返回规定的最小输出结构
- [ ] 不声称完成 RTL、testbench 或日志专业分析
- [ ] 输出结构符合设计约定

#### 缺少输入

- [ ] 明确报告缺失输入
- [ ] 不会强行推断关键技术参数
- [ ] 输出中包含"需要更多信息"标识

#### 正常场景（仅限 smoke 输入）

- [ ] 只有指定 smoke 输入才执行最小 Procedure
- [ ] 正确选择 Agent
- [ ] 不响应真实工程请求
- [ ] description 明确限制为 Milestone 1 smoke 测试

- [ ] 只有指定 smoke 输入才执行最小 Procedure
- [ ] 正确选择 Agent
- [ ] 上游 Agent 结果能被下游消费
- [ ] 能调用 hello CLI（适用于 rtl-to-testbench）

#### 单 Agent 流程（rtl-architecture-analysis、simulation-analysis）

- [ ] 能调用单个 Agent
- [ ] 能读取 Agent 输出
- [ ] 能汇总结构化输出

#### 双 Agent 流程（rtl-to-testbench）

- [ ] 能串联两个 Agent
- [ ] 上游失败时不继续调用下游
- [ ] 能调用 hello CLI
- [ ] 能汇总所有结果

#### 不完整输入

- [ ] 不完整输入被阻断
- [ ] 请求用户补充明确缺失项
- [ ] 不会盲目猜测

---

### OMP Smoke

#### Skill 发现

- [ ] 三个 Skill 被真实发现
- [ ] Skill 名称和描述正确
- [ ] OMP 不报告错误

#### Agent 调用

- [ ] 三个 Agent 被真实调用
- [ ] Agent 返回预期输出结构
- [ ] 调用成功无错误

#### Reference 读取

- [ ] reference 能被读取
- [ ] reference 内容正确
- [ ] 读取操作成功

#### Agent 输出消费

- [ ] Agent 输出能被主会话继续消费
- [ ] 临时交接机制正常
- [ ] 不会出现输出丢失

#### CLI 执行

- [ ] hello CLI 能被 Skill 流程调用
- [ ] CLI 返回预期结果
- [ ] 集成执行成功

#### 失败报告

- [ ] Agent 失败能被明确报告
- [ ] 失败信息正确传递
- [ ] 不会隐瞒失败

## Fixture 定义标准

### 1. 正常 Fixture (Normal Fixture)

**特征**：
- 输入完整、格式正确
- 预期输出明确
- 场景规模较小
- 结果可自动或人工精确校验

**用途**：
- 验证基本流程
- 验证 Tool
- 验证 Agent 调用
- 验证输出结构

---

### 2. 错误 Fixture (Error Fixture)

**特征**：
- 输入中包含已知错误
- 错误类型和预期行为已知

**示例**：
- RTL 语法错误
- testbench 故意失败
- 时序报告存在负 slack
- 参考模型端序错误
- 定点精度不一致
- 仿真日志包含 assertion failure

**用途**：
- 验证 Skill 能识别问题
- 验证不会伪造成功结果
- 验证失败处理路径

---

### 3. 不完整输入 (Incomplete Input)

**特征**：
- 缺少关键文件、字段或语义

**示例**：
- 未指定顶层模块
- 缺少时序报告
- 缺少波形文件
- 寄存器语义未定义
- 缺少参考模型

**用途**：
- 验证 Skill 能明确指出缺失项
- 验证不会盲目猜测关键接口语义

---

### 4. 真实工程样例 (Real-world Sample)

**特征**：
- 来自实际项目的模块、日志或报告
- 规模和复杂度接近真实场景
- 可能包含已知或未知问题

**用途**：
- 验证 Skill 在真实场景中的实用性
- 验证鲁棒性
- 不要求所有真实样例首版通过

## 真实工程样例

### 存储位置

真实工程样例不应默认叫 Fixture。建议：

```text
fixtures/       可提交、可重复、预期明确的小型样例
real-samples/   默认本地或脱敏后的真实案例
evals/          case 定义、rubric 和结果
```

### 数据治理

- 专有工程默认不提交仓库
- 可使用本地路径或样例清单
- 进入仓库前需要脱敏
- 大型 FST、日志和二进制数据应由生成脚本产生或使用外部引用
- 记录代码版本和输入哈希

### 记录格式

```markdown
## 样例名称

- 来源：项目/模块名称
- 存储位置：local/或 real-samples/
- 复杂度：简单/中等/复杂
- 已知问题：无/已知问题列表
- 当前状态：支持/部分支持/不支持
- 差距记录：...
```
